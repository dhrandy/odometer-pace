Odometer Pace API

For AI agents and scripts. Create a key in Settings, then send it as a Bearer token. A key can add and read odometer readings and read the status. It cannot see or change settings, logins, or other keys. Readings added with a key are labeled with the key name and the person who owns it.

Authorization: Bearer op_...

GET /api/v1/status

Everything in one call: lease facts, today's allowed odometer, how the newest reading compares, and all readings.

curl -H "Authorization: Bearer $KEY" https://YOUR-HOST/api/v1/status
{
  "configured": true,
  "today": "2030-04-05",
  "lease": { "start_date": "...", "end_date": "...", "total_miles": 36000,
             "odometer_limit": 36010, "day_of_lease": 36, "days_total": 1096, "state": "active" },
  "allowed_odometer_today": 1210,
  "latest": {
    "date": "2030-04-05", "odometer": 1150,
    "on_pace_odometer": 1210, "miles_over_pace": -60, "pace_status": "under",
    "miles_used": 1140, "miles_remaining": 34860,
    "miles_per_day_so_far": 31.7, "miles_per_day_to_stay_under": 32.9,
    "projected_end_odometer": 34750, "projected_vs_limit": -1260, "days_left": 1060
  },
  "readings": [ { "date": "2030-04-05", "odometer": 1150, "source": "api:Instinct" } ]
}

Numbers above are an invented example. miles_over_pace is negative when you are under. latest is null until the first reading.

The warning field

/api/v1/status includes warning: {"level", "message", "stale_note", "days_since_reading"}. level is none (on or under pace), watch (over pace, but projected to finish under the limit), warning (projected to finish over the limit) or urgent (a large projected overage, already past the limit, or very few miles per day left). message says it in plain words and is empty when the level is none. message mentions the planned change when one is set (see lease.planned_change and latest.projected_includes_plan). stale_note is set when the last reading is more than 10 days old.

POST /api/v1/readings

Save an odometer reading. date is optional (YYYY-MM-DD) and defaults to today on the server. One reading per date, a second one replaces the first. The odometer cannot go lower than an earlier reading.

curl -X POST https://YOUR-HOST/api/v1/readings \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"odometer": 1150, "date": "2030-04-05"}'

Returns {"saved": {...}, "replaced": false, "previous": null, "status": {...}} on success. When the date already had a reading, replaced is true and previous holds the old odometer, because the API replaces without asking, or {"error": "..."} with HTTP 400 and a plain reason.

GET /api/v1/readings

Just the readings, oldest first.

GET /api/v1/glance

Small read-only summary for widgets. Returns 404 until the admin turns on the glance view in Settings.

{ "today": "2030-04-05", "vehicle": "", "state": "active", "status": "on_track",
  "level": "none", "reading_date": "2030-04-04", "days_since_reading": 1,
  "miles_over_pace": -60, "can_drive_today": 31, "can_drive_week": 274,
  "miles_remaining": 34860, "average_per_day": 32.9 }

can_drive_week is the miles you can drive from your latest reading through the end of the sixth day from today and still be on pace. status is on_track or over. Invented numbers.
